\section{システムの構成と処理フロー}
本システムは，定期的に起動される算出処理，データ管理および外部連携を担う本システム独自の Web API，ユーザへの情報提示を行う Web アプリケーション，および Slack API から構成される．
システム構成の概要を図\ref{fig:composition}に表す．
これらの要素が連携し，帰宅推奨時刻の算出から情報提示，投票の取得および集計までを一貫して行う．

帰宅推奨時刻の算出は，定期的に起動される処理によって実行される．
有効な時間帯が算出された場合，その結果は本システム独自の Web API を介してデータベースに保存されるとともに，Slack API を通じてユーザへの通知が行われる．
この定期実行には GitHub Actions を用いており，あらかじめ設定したスケジュールに従って Web アプリケーション上の API が呼び出される．
これにより，ユーザの明示的な操作を必要とせず，帰宅推奨時刻の算出および Slack への通知が自動的に行われる．


本システム独自のWeb API は，本システムにおけるデータ管理および外部サービスとの連携を担う．
具体的には，算出された帰宅推奨時刻の保存，Slack から送信される投票イベントの受信，投票内容の記録，および締切後の集計処理などを担当する．
これにより，フロントエンド側は表示やユーザインタフェースに専念でき，処理の責務分離が実現されている．


ユーザへの情報提示は Web アプリケーションを通じて行われる．
画面上には投票対象となる帰宅時刻の候補の表示とあわせて音声通知を行い，ユーザが提示内容に気づきやすい設計としている．
また，この Web アプリケーションは定期的に Web アプリケーション上の API を呼び出し，帰宅推奨時刻の算出処理や Slack 通知を実行する役割も担っている．


Slack は，本システムにおける入出力インタフェースの一部として利用される．
ユーザは Slack 上から投票ができ，その内容は Slack Events API を通じて Web API に送信される．
一方，通知については Slack Web API を用いて送信される．
これにより，ユーザは日常的に使用しているコミュニケーションツール上でシステムと関われる．


% これらの構成要素は互いに連携して動作し，ユーザに対して帰宅推奨時刻を提示し，投票を受け付け，その結果を集計して反映する一連の処理を実現している．


本システムの具体的なシステムフローを以下に示す．
\begin{enumerate}[label=\textcircled{\scriptsize\arabic*}]
  \item GitHub Actionsで公開したWebアプリケーションの API を定期実行し，帰宅推奨時刻を算出
  \item 有効な時刻が算出された場合，本システム独自の Web APIを呼び出して保存・最多区間内のメンバに通知
  \item 画面に投票の選択肢を提示し，音声通知
  \item バックエンドがSlack Events APIを通じて投票を受信しデータベースに保存
  \item 投票締切後，結果を集計
\end{enumerate}


なお，本システムの実装には，Web API の構築に Go 言語を用い，データの永続化には MySQL を使用している．
バックエンドはDockerを用いてコンテナ化されており，外部からアクセス可能なサーバ環境上で稼働する．
Web アプリケーションは Next.js を用いて構築し，ブラウザ上での画面表示および音声通知を実現している．
Slack との連携には Slack Events API および Slack Web API を利用し，通知の送信と投票の受信を行っている．
これらの構成要素は HTTP 通信を介して連携しており，機能ごとに独立した構成にし柔軟な拡張や保守が可能な設計としている
